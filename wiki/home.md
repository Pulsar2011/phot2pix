# phot2pix

**From photons to pixels: a statistically faithful simulator of image-sensor readout.**

phot2pix converts a photon flux falling on each pixel of a detector into the digital numbers (ADU) that the detector's electronics would produce. That includes the noise, the reset level, the readout sequence and any onboard processing given users implementation of the onboard pipeline. It is a C++23 library developed by W. Gillard, Assistant professor at Aix-Marseille University, CNRS/IN2P3, CPPM.

phot2pix does **not** model optics. It requires as input the incoming flux on each pixel (in photons/s); All optical effects, including the PSF, sky background, and light sources, must be modelled upstream and included in the input given to phot2pix. Phot2pix output are FITS data cube.

---

## Two parts

| Part | Where | Content |
|---|---|---|
| **The generic core** | `src/phot2pix/` | Instrument-agnostic: a pixel model, a detector array, a configuration system. Nothing in it knows about a particular instrument. |
| **Instrument examples** | `src/nisp/` | A complete instrument built on top of the core: the Euclid NISP HAWAII-2RG infrared detectors, with their readout modes, noise sources, full well and non-linearity, inter-pixel capacitance, crosstalk between channels, persistence and onboard slope fitting. |

An instrument is added by **inheriting** from the core and **composing** its building blocks; the core itself is never modified. The NISP example is the reference for how to do that.

## Where to start

- **[Philosophy](Philosophy)**: This section describe how phot2pix is organised and why: the four layers, the *reset → integrate → read* pixel model, units, configuration, how to extend the library, and how it is tested.
- **[NISP example](NISP-example)**: this section describe how the **core** of phot2pix can be inherited to model specific detector behaviour. The example focuses on the Euclid/NISP H2RG simulator: it provide architecture and pipeline, model for the different pixel response and pixel correlation, a configuration reference giving the physical meaning and unit of every parameter, readout modes (MACC, UTR, CDS, FLUX, DPU). This example come with a command line tools `nispSimulator` to run basic simulation based on configuration file and its validation.
- **[Sequences of exposures](ScenerySequencer)**: `ScenerySequencer`, a series of exposures on one detector (persistence carries over), how to derive it for an instrument, with the NISP override as the example. Note that at this stage the scene generators still to be written.

For build instructions and dependencies, see the `README.md` at the root of the repository.
